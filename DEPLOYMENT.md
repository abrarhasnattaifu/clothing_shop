# MamaCloset deployment setup

The application uses Vite's `@/` alias for frontend source imports. These imports resolve from `frontend/src` and do not depend on the local Windows folder or the server's filesystem layout.

## Frontend

1. Copy `frontend/.env.example` to `frontend/.env` for a local deployment build, or set the variable in the frontend hosting provider.
2. Set `VITE_API_URL` to the backend's public origin, such as `https://api.example.com`. Do not add `/api` at the end. If the frontend host reverse-proxies `/api` and `/uploads` to the backend on the same origin, leave this variable unset.
3. Build and deploy the contents generated by `npm run build` from the `frontend` directory.

Vite embeds `VITE_API_URL` into the frontend at build time, so set it before building. A changed backend origin requires a new frontend build, but not a source-code edit.

## Backend

1. Set the variables listed in `backend/.env.example` in the backend hosting provider. Keep passwords, email app passwords, and `JWT_SECRET` private; do not commit a real `.env` file.
2. Set `CORS_ORIGIN` to the frontend's exact public origin. Multiple allowed origins can be comma-separated.
3. Configure the provider's MySQL connection values and run the SQL schema and migration files from `database` against that database before starting the application.
4. Start the backend with `npm start` from the `backend` directory. The server listens on the provider's `PORT`.
5. Use persistent storage for `backend/uploads`; profile and product image files are stored there.

The hosting provider, public URLs, database credentials, email credentials, and payment contact details are deployment settings, not hard-coded source paths.
